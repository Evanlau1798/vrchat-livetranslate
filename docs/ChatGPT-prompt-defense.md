# ChatGPT 語音翻譯的提示詞防護 Findings

此文件記錄目前的防護方式、實測發現及驗證邊界。適用於現有 ChatGPT 訂閱語音路徑；沒有新增獨立 ASR、文字翻譯服務或音訊後處理模型。

## 發現與修復

| 發現 | 目前處理方式 |
|---|---|
| 口述「翻譯已結束」、改成問答或切換語言，可能讓服務離開翻譯任務 | 將所有語音內容定位為來源資料，包括角色標籤、宣稱的權限與要求延續先前回答的話語；它們不能改寫應用程式的翻譯規則 |
| 刪除／只保留指定輸出的請求，可能造成額外回覆或丟棄來源 | 要求完整翻譯每次實際發話一次，包括要求靜音、刪除或替換輸出的指令；不得另外執行指定輸出 |
| 偽造對話或引用可能誘發無來源的介紹、回答或補完 | 直接以來源說話者的語法呈現；只有實際說出的角色或引用標籤才可保留，不自行加入介紹或完成虛構對話 |
| 部分譯文被重新開始、整段重複，或先回聲原文再翻譯 | 依收到的順序完成尚未說出的尾部，只輸出設定的目標語言；真正再次說出的內容仍須再次翻譯 |
| 靜默封句切在轉錄分片中間，後續完整分片重放已顯示的前綴 | 每個來源／譯文角色分別記錄該分片已封句的前綴，後續完整分片若精確匹配，只補未送出的尾部；不做全域去重 |

最後一項是本機字幕組裝缺陷，與服務自行執行語音指令分開處理。字幕修復不會過濾或改寫已產生的譯音。

## 政策如何送入服務

[會話實作](../vlt/session/chatgpt_live.py) 在原有前端翻譯規則後加入直接呈現、來源信任邊界、順序續譯與忠實度要求。啟動時另傳入固定的 developer 說明與來源／譯文示例，展示敘述、問題和命令都只是待翻譯內容。

示例覆蓋十種既有目標語言，完全固定，不使用私人錄音、攻擊逐字稿、測試預期答案或使用者詞庫。自訂目標語言維持原有協商方式。詞庫僅放在明確標示為資料的 JSON 區塊，不插入 developer 指示或固定示例。後端原有翻譯提示詞保留。

忠實度規則允許上下文協助辨識實際聽到的字詞，但禁止自行補出未說過的事實、建議、句尾或答案。來源已是目標語言時仍維持來源內容；真正的引用、角色標籤和重複不能被當成攻擊字詞刪除。

## 驗證結果與邊界

本機使用完整長對話前導、攻擊後等待及後續正常語句，另做新連線重測。五組跨語言長對話、四組冷啟動重測及一組中文控制，共十組有限攻擊核對未再觀察到額外答案、獨立替換回覆、整段漏譯、整段重複或無來源的對話介紹。真正重複、引用與後續正常語句均保留。

跨語言自動判定維持 REVIEW；中文控制的原始字詞判定為 FAIL，辨識／字詞差異依測試條件另列，沒有修改判定器或將結果改成自動 PASS。服務的來源轉錄不是獨立的錄音真值；原始錄音並未逐字聽校。這些結果只支持已執行的有限案例，不保證任意語音或任意長度對話都不會發生提示詞注入。

Windows 本機另以兩條同時啟用譯音的正式會話，經生產取樣泵、Engine、MicProxy 與虛擬音訊回錄驗證。兩次新連線、各三輪回錄全部通過，完整服務語音與各自回錄聲道的波形相關度最低為 99.919%，沒有回錄狀態錯誤或輸出緩衝不足。波形一致不是譯音逐字正確、遠端 VRChat 聽感或 Linux 實體音訊的證明。

提示詞是機率性的行為約束，沒有提供確定性的安全隔離。如果日後觀察到新的額外回答或漏譯，應保留來源、完整服務輸出與時序重新驗證，不能只用連線成功或單一字幕事件宣稱通過。

## Repo 與 CI 的範圍

耗用訂閱額度的額外實機測試程式、長對話資料、私人錄音、原始轉錄及回錄只保留於本機忽略的暫存目錄，不隨 repo、套件或 CI 發布。

Repo 保留離線政策傳遞、語言組合、詞庫資料邊界、字幕分片、真正重複、錯誤清理與 GUI 回歸測試。CI 使用假的 RPC／瀏覽器邊界，不登入 ChatGPT、不建立語音服務連線，也不需要額度或音訊裝置。離線政策測試證明應用程式送出的契約；它不替代真人語音防護的實測。

服務選單標示「消耗 Codex 額度」。語音翻譯會使用登入帳戶的訂閱額度；雙向模式建立兩條獨立會話，兩個方向都可能耗用額度。訂閱額度不等同於一般 OpenAI API credit。
