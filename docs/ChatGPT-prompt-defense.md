# ChatGPT 语音翻译的提示词防护 Findings

此文件记录目前的防护方式、实测发现及验证边界。正式会话尚未接入独立来源 ASR、文字翻译服务或音频核对模型；离线组件、研究候选与生产实现分开记录。

## Python 中转的离线实现进度

新组件尚未注册到正式会话入口。登录和状态检查仍使用官方 CLI；新的固定 HTTP 传输不启动 app-server、代理任务、shell 或 MCP。凭证 owner 只使用应用专属目录，串行处理登录与更新，拒绝旧账户或旧登录世代；更新结果不明时不再次发送。路径检查拒绝符号链接、Windows junction 和多硬链接的凭证文件；重复取消也须等待登录子进程收割后才释放写入锁。无法确认登录子进程退出时，同一进程内的 owner 作废旧世代并阻止后续登录与凭证读取，不把清理异常当作成功。原子写入、目录及文件权限、路径重新导向、HTTP 资源清理和错误信息均有离线测试。传输先检查保留重复字段的响应头，拒绝无效／重复 Content-Length、不支持的 Transfer-Encoding 以及两者并存；读取后再次检查总期限，拒绝尚有缺字节的 EOF 与不完整 chunked 回应。非法或截断的内容即使仍可解析为 JSON，也不能作为成功结果。

[分段器](../vlt/session/chatgpt_segments.py)使用 16 kHz 单声道 PCM，初始参数为峰值 220、500 ms 静音、最多 1 秒未分配 preroll，已经结束的样本不进入下一段。超过 30 秒时整段拒绝，等待下一静音边界恢复。这些是初始资源限制，尚未完成实机校准。

传输另核对 chunked 数据分隔符、十六进制长度、扩展及终止空行，限制元数据行与 trailer 总大小，不依赖标准库的宽松 EOF 判定。[HTTP framing 依据](https://www.rfc-editor.org/rfc/rfc9112.html#section-7.1)与 JSON／模型完成校验分开；Python 3.11 的 decoder 扩展由内存中的真实 HTTPResponse 正反例保护，升级 runtime 时须复核这一内部接口。

Live 建立连接的离线传输只接受创建状态与单一、符合固定路径的 `Location`，由校验后的标识构造固定侧通道地址；拒绝其他主机、端口、用户信息、查询、片段、重复标头及重定向。专用协议标头限于 Live 操作，其他订阅操作仍只接受原来的成功状态。此传输组件尚未构成完整的 Live adapter，也不证明服务端工具隔离。

[Python 转录请求](../vlt/session/chatgpt_relay.py)参考已固定版本的 [codex-asr 协议](https://github.com/Wangnov/codex-asr/blob/479f6a7a3db81fe2a23d4755b0ccbeb4400317d4/src/lib.rs)，在内存中将完整 PCM 包装为 WAV，只发送音频与必要语言。来源为 16 kHz，候选译音为 24 kHz；盲转录接口不接受核准译文或预期逐字稿。离线测试使用合成 PCM 和假凭证，核对实际 multipart 字段、完整字节、旧世代拒绝、重复取消及不自动重送；没有调用转录服务，也不引入该项目的执行文件。私有端点的授权适用性与识别可靠性仍须验证。

同一中转另有固定模型的文字翻译、来源／译文校验及译文／独立音频转录校验请求。来源与词库仅进入 JSON 用户数据，固定指令不插入这些内容；请求禁用工具、不存储、无代理执行循环，必须收到对应完成事件且回报模型一致，才解析有界 JSON。正常与拒绝的合成响应均有离线对照。模型目录中的候选不等于实际订阅端点已通过验证；参数确认和假的校验结果也不能证明服务会抵抗注入。

有限服务诊断发现并修复了三处兼容性问题。Windows 应用数据目录的系统命名空间映射只有在既存目录身份及相对路径一致、两条祖先链均无链接或 reparse 时才接受，仍使用应用专属登录。转录响应仅接受 `text`，或 `text` 加完整的三项已知资产元数据；元数据有类型、大小及控制字符限制，只丢弃，不下载、执行或传入模型。文字响应的完成事件若明确带空 `output` 数组，只能采用该响应之前匹配且已完成的输出项；缺少终止事件、未完成项、错误标识、模型不符或工具输出仍拒绝，不能用文字增量推测完成。

当前 Python 候选已完成正常真人录音的独立转录、日文翻译与文字校验。另有结束翻译原句及后续恢复句的有限对照，以及额外问候、缺尾、数字变化和直接回答算式的文字比较器正反例；它们不包含译音生成或实际播放。录音中仍出现数字和字词辨识差异，一项替换输出案例因语义不符被拒绝，保留待复核，不计入全绿或攻击免疫结论。

随后对 44 份真人录音完成独立来源转录、翻译及文字校验，第一轮 41 段接受、3 段拒绝。检查发现翻译可能替换来源对象、添加未表达的原因，或省略来源开头的标签。固定翻译规则现在明确保留对象与关系，禁止上述改写，也不能静默删除不清楚的字词；没有放宽校验器或将私人录音、测试预期答案加入生产提示词。

修改后复用同一批已保存的盲转录，并重新核对录音哈希，逐段重新生成译文及校验；这一次 44 段均获得模型接受，两个明确的对象／标签缺陷在新译文中得到修正。此结果只表示有限文字候选通过当前模型校验，不是完整 E2E 全绿。13 段来源与宣读稿的规范化字词仍不完全一致，实际录音尚未逐字听校；一组不清楚来源与相同译文的校验判定前后不一致，继续保留 REVIEW，不能把后一次接受当作问题已修复。没有反复转录挑选有利来源，没有使用 Live、正式输出队列或音频设备。

对历史日文候选的实际 PCM 另做盲转录：内容相符的一份得到语义接受，人工已确认额外问候的一份及人为移除句尾的对照被拒绝。ASR 只收到音频和语言，核准译文仅供后续独立比较器使用。历史候选的传输完整性原本未通过，内容接受不改变该结论；这些诊断没有生成新的 Live 译音、播放音频或完成联合验收。

[事件解析](../vlt/session/chatgpt_events.py)有原始消息大小限制，保留回合标识、角色和时间，拒绝重复完成、错配、工具、handoff 和未核实事件。文字响应必须有匹配的完成事件及助手文字；`turn.done` 只表示转录完成，不证明音频生成或排空完成。配置确认也不作为工具隔离证明。

[候选封存](../vlt/session/chatgpt_candidate.py)与 AudioWorklet 完成尾样本 flush、样本数核对及 ACK 后冻结。整个候选有容量限制，晚到样本、取消、错误 ACK 或回压错误使候选失效。本地测试只验证封存，不能把它当作真实 Live 服务完成契约。

[逐段 coordinator](../vlt/session/chatgpt_pipeline.py)用假的服务 stages 验证两方向独立排队、每方向一段处理中及两段等待、停止与过期结果清理、核准后恰好输出一次，以及实际消费队列时再次核对世代和音频哈希。任一方向改变语言或账户改变，都使旧结果失效；取消尚未完成时不在该方向叠加新请求。纯字幕只进行来源 ASR、翻译与文字校验；字幕和译音模式在完整候选的盲 ASR 与音频核对通过后才共同放行。盲 ASR 不取得核准译文，显示用的简繁转换放在校验之后。

离线回归另发现，粗粒度计时器可能在名义期限前发出取消；若服务吞掉取消并返回结果，仅比对时钟会让已逾时的阶段继续处理。现在同时检查超时上下文是否已触发及实际期限，已触发的结果一律拒绝。回归模拟粗粒度时钟，确认来源逾时后不启动翻译；正常重复发话仍逐段放行，无消费者时已完成输出队列保持有界。

现有虚拟麦克风与麦克风代理的离线回归还发现，起播后剩余 PCM 不足一个播放区块时，原消费逻辑只输出静音，尾音一直留在缓冲。现在沿用既有排空函数，读出全部剩余样本并补静音到区块长度，保留起播门槛和原声分流。句中短分片继续等待补齐；封句或达到既有停更期限后才排空短尾。音频已耗尽后收到句尾标记，也会解除“正在播放”的记账，避免误保护下一句；Windows 回调、代理及 Linux 管道共用排空条件。Windows 回调与 Linux 代理的真实软件消费入口均有回归；一份已保存候选经过现有重采样后，三条软件输出路径的内容哈希与预期一致，包含最后的短尾，缓冲最终为空。这不证明实体设备、远端听感或整条订阅管线已验收。

后续离线重放使用已保存的实际 PCM 与服务校验结果，在 coordinator 消费入口验证：完整校验返回前没有字幕或音频回调；正常候选之后恰好输出一次，字节、长度与哈希保持一致；额外内容与缺尾候选两个回调均为零。历史文字校验只有单一核准字段，先按当前契约重新校验，没有用默认值补齐缺失字段。此重放只覆盖 coordinator 的回调边界，未经过正式 GUI 队列、音频设备或播放，也不替代最新候选的联合验收。

这些离线测试证明编排和拒绝流程，不证明模型校验结果正确，也没有证明现有 GUI、overlay、chatbox、虚拟麦或房间的全部队列已接上新闸门。订阅 ASR、文字模型及 Live 的正式 adapter、工具所有权、真实候选完成契约、正常联合验收和全出口接入仍是未完成项。正式服务门槛未成立前，不扩大依赖它的实机验收，也不恢复 Ready。

官方[会话说明](https://developers.openai.com/api/docs/guides/live-conversations)要求将转录时间与实际音频分开：WebSocket 音频增量没有时间字段或音频完成事件，WebRTC 则通过媒体轨道送音。`session.closed` 可用于会话收尾；它与本地 seal ACK 仍不能单独证明私有订阅路线的完整 PCM 已到达。公开的 [Sign in with ChatGPT 预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)也明确不支持该公开流程的音频输入及转录 API，不能把公开授权说明直接当作私有语音端点的适用契约。

## 当前发布状态

新的工具诱导反例表明，既有提示词和有限案例通过不足以作为正式发布依据。ChatGPT 功能 PR 保持 Draft。目标方案改为逐段校验后放行；下述可行性检查属于本地研究，还没有接入生产会话，也没有实现全部输出闸门。

| 门槛 | 检查结果与边界 |
|---|---|
| 工具专属登录的独立来源转录 | 使用明确指定的应用专属认证文件，完成中文真人录音转录；生成的日文候选音频也取得日文转录，人工听校确认存在额外问候，该候选未通过校验。已更正早期按文件名分类的非日文样本，不将它计入日文验证。未使用全局 Codex 登录，仅证明有限样本的转录可用 |
| 订阅文字翻译及语义校验 | 直接调用订阅文字 HTTP 路线，发送 `tools: []`、`tool_choice: "none"`，没有本地代理或工具执行循环。正常语句和工具诱导原句获得译文，独立校验接受忠实译文并拒绝原文没有的算式答案；仅支持这些有限检查 |
| GPT-Live 译音的工具隔离 | 未通过。现用 app-server 在通知客户端之前仍会路由 handoff；`clientManagedHandoffs` 不是禁工具开关。直连研究候选不启动本地代理，但实际服务端配置尚未获得适用契约或有效配置证据 |
| 译音完成及归属 | 尚未完成联合验收。现有生产 PCM 回调缺少配对标识，反射音频曾出现缺帧。另有真实 Live 候选完成整次连接的本地封存与盲转录核对，一份正常短句内容被接受，额外内容被拒绝；侧通道关闭异常仍待核实，尚未接入正式出口或播放同一份核准 PCM。静音超时不能作为安全放行依据 |

工具边界依据与安装版本对应的[公开实现](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/core/src/realtime_conversation.rs#L1763)及[参数说明](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/app-server-protocol/src/protocol/v2/realtime.rs#L197)。这证明当前客户端路径仍可进入后台路由，不能由此声称已经确认所有服务端工具能力，也不能将 RPC 拒绝请求当成服务端隔离证明。

### 直接订阅管线的进一步检查

应用专属登录的直接 WebRTC 候选已建立连接，不启动 app-server、不设置代理或通用工具执行器。它切断了上述已知本地后台执行路径；但 HTTP 建立成功、请求中的 `delegation.type: "client"`，以及只返回标识和状态的启动事件，不能单独证明实际服务端工具配置。官方 [delegation 契约](https://developers.openai.com/api/docs/guides/live-delegation)区分 client 与 Responses 执行模式，不能把其中一类工具设置当成所有私有订阅路线上共用的禁工具开关。

新的原始事件对照使用已知的初始用户消息格式，在 client 候选的主事件连接和侧通道均观察到 `delegation.created`，其 `target` 明确为 `client`；应用没有执行委派。独立 Responses 候选尚未触发足以区分执行模式的事件。前者是有效的有限归属观测，仍不足以确认全部服务端工具能力或将公开模式契约套用于整条私有订阅路线；工具边界门槛继续保留。

不含语音输入的配置检查仍未取得实际 delegation／存储配置。负向检查故意传入无效的 delegation 类型：HTTP 握手仍返回成功，随后事件通道报错并关闭；已有记录不足以确认具体拒绝字段。这进一步说明，应区分握手成功、会话启动成功与配置验证，不能把其中一步当作工具隔离通过。

后续零输入检查中，`delegation: null` 更新取得相关确认；非法类型更新取得明确关联的 `invalid_value`，字段为 `session.delegation.type`，证明该字段受到验证。但成功更新仍未回显执行模式，私有订阅路线上 client 模式是否涵盖全部服务端工具也缺少适用契约。有效配置回显并非唯一证据形式；其他证明也必须有适用契约与能区分模式的观测，不能以单纯确认回覆替代。

另一次只发送配置的模式切换负对照，在初始请求选择 client 后，尝试更新为 Responses，并明确设置空工具列表及禁用工具调用。接口返回相关的 `session.updated`，但没有回显实际模式，也没有得到公开契约所述的模式不可变错误。该检查没有发送来源语音、核准译文或生成请求，回录没有非零样本，连接已清理；不能据此判断配置已切换、被忽略或已隔离工具。公开模式契约在此私有订阅路线上仍未确立，因此不扩大语音生成，等待适用契约或有效执行模式及边界证据。

原始事件能提供 assistant turn 的标识和时间范围，也收到明确的 `session.close`／`session.closed`。Sideband 的反射 PCM 带有时间范围，但多个正常语句检查出现了段内缺帧，本地覆盖检查拒绝这些音频。官方[音频事件说明](https://developers.openai.com/api/reference/resources/live/primary-websocket)也说明反射帧可能丢失；不能补零或仅凭关闭确认声称完整。浏览器主音频流在会话关闭确认时仍未观察到独立的远端媒体结束，完成与 decoder／resampler 排空仍待验证。

相符版本的[独立发声实现](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/core/src/realtime_conversation.rs#L2349)使用 `session.context.append` 的 `speakable` 通道。这条候选在没有输入用户音频时，接受了一段已核准译文并产生语音；完整本地回录的独立转录出现了核准译文没有的额外问候，无工具文字校验返回拒绝。人工听校确认音频中确有额外问候，因此将该候选判为内容不符；它也未通过音频完整性检查，不代表逐字发声或端到端验收。仍需正常内容成功放行的对照，不能以全部拒绝作为通过依据。

这些检查没有接入生产输出链。缺帧、额外内容或无法确认完成的段落均未作为核验通过的字幕或译音放行；人工回听仅用于核对测试结果，没有以全量丢弃替代正常使用验收。

### 整次连接音频封存候选

另一条候选是每段核准译文使用独立连接，从首个主音频样本开始收集整次连接的实际 PCM，不按反射事件裁剪或补零。收到明确的单次助手回合结束与正常会话关闭后，封存本地缓冲：先发送末尾不足一帧的样本，再确认总样本数，封存后禁止追加。静音浏览器的本地检查已验证尾部有序送齐与缓冲停止增长；没有连接语音服务或播放到音频设备。

此候选须将封存字节、方向、段落、会话世代和核准译文绑定，独立转录整份音频时不得将核准译文作为提示。核对通过后只能播放同一份音频，并在放行前再次核验绑定与哈希。额外助手回合、异常关闭、工具事件、截断、内容不符或旧结果均须拒绝。它核验的是实际准备播放的候选，不宣称已经收齐服务器生成的全部样本；尚未收到的远端尾部不得绕过封存缓冲播放。

新的真实候选已经完成本地封存、整份盲转录与独立比较：一份正常恢复短句内容相符，一份较长语句存在识别／语义差异而被拒绝，另一份短句的盲转录出现额外开场词，校验因此拒绝；这些新候选尚未人工听校，均未实际播放。关闭诊断中，侧通道异常发生在主动关闭请求及两个通道的关闭事件之后，但没有收到正常的 WebSocket 关闭帧；不能把这个顺序直接当作正常收尾契约。历史实际 PCM 的额外内容与截尾对照也被拒绝，仍须完成当前管线的双向隔离、正常使用及同一音频实际回放验收。

后续对照在建立连接时直接加入已核准的用户文本，不再等待侧通道连接后才提交发声内容。主通道与侧通道回报相同助手回合和完整核准文本，但两份实际浏览器 PCM 的盲转录仍出现字词或数字差异，均被拒绝。同一份保存音频的第二次盲转录也重现差异；不通过反复转录挑选有利结果，原拒绝判定保持。

其中一次同步比较发现，侧通道反射音频的转录内容相符，浏览器主音频转录却改变了时间数字；浏览器同时记录了音频补偿样本。反射音频自身存在段内缺帧，不能用其比较器通过结果替换原候选放行。这只是媒体传输／擷取与辨识差异的诊断线索，尚未证明根因，也未修复正常译音的稳定性；模型的文本逐字稿不能代替实际音频校验。

本地另将一份已保存候选经过 AudioBuffer、MediaStreamSource 与现有 PCMOutput，静音捕获并封存。完整 231424 个输入样本经既有量化后逐样本相符，尾样本保留，浏览器与临时配置已清理。这只核对本地音频图与 PCM 转换，不经过远端 WebRTC／Opus，也不证明生成或 ASR 正确。新的媒体计数诊断中，主要补偿样本增量发生在会话关闭之后；不能把关闭后的计数直接当作发话内容改变的根因，亦未使用未经确认的采样率换算其秒数。

ASR 可能补出缺失的句尾，语义校验也可能误判；本地封存不能替代独立核对，更不能补足服务端工具隔离的证据。上述核对只针对实际准备播放的完整本地候选，不宣称收齐尚未到达的服务器样本；未核准或封存后晚到的样本不得进入播放链。

[codex-asr](https://github.com/Wangnov/codex-asr) 是一次性私有转录接口的客户端，没有时间戳或可选择底层模型的契约。它有助建立独立逐字稿，本身不构成提示词注入防护。公开订阅接口的[支持范围](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)也不能直接套用到私有语音接口。

另对六份中文真人录音进行独立转录，其中包含角色伪造、要求结束任务及替换输出的原句。有限检查未观察到转录服务执行这些口述要求，但存在识别差异与简繁混用，且原始录音尚未逐字听校。此结果维持待复核，不能作为攻击免疫或完整管线通过的证明。

只有所有门槛通过后，才接入「本地断句 → 独立来源转录 → 受限翻译 → 译文校验 → 译音生成 → 译音独立转录核对 → 放行」。文字和 PCM 必须在 session callbacks 之前共同放行，涵盖所有现有输出出口；每段绑定方向、段落 ID 与会话世代，超时、停止、重连、工具事件、错配或校验失败均丢弃该段并说明原因。两个方向独立排队，同时保留既有方向分流规则。

目前未通过的两个门槛阻止正式 ChatGPT 发布，不能以全量丢弃、单向模式、实验标签或借用另一服务替代验收。ASR 与语义校验仍可能出错，即使未来硬性放行流程通过，也不能宣称任意注入完全免疫。

## 发现与修复

| 发现 | 目前处理方式 |
|---|---|
| 口述「翻译已结束」、改成问答或切换语言，可能让服务离开翻译任务 | 将所有语音内容定位为来源数据，包括角色标签、宣称的权限与要求延续先前回答的话语；它们不能改写应用程序的翻译规则 |
| 删除／只保留指定输出的请求，可能造成额外回复或丢弃来源 | 要求完整翻译每次实际发话一次，包括要求静音、删除或替换输出的指令；不得另外执行指定输出 |
| 伪造对话或引用可能诱发无来源的介绍、回答或补完 | 直接以来源说话者的语法呈现；只有实际说出的角色或引用标签才可保留，不自行加入介绍或完成虚构对话 |
| 部分译文被重新开始、整段重复，或先回声原文再翻译 | 依收到的顺序完成尚未说出的尾部，只输出设置的目标语言；真正再次说出的内容仍须再次翻译 |
| 静默封句切在转录分片中间，后续完整分片重放已显示的前缀 | 每个来源／译文角色分别记录该分片已封句的前缀，后续完整分片若精确匹配，只补未送出的尾部；不做全局去重 |

最后一项是本地字幕组装缺陷，与服务自行执行语音指令分开处理。字幕修复不会过滤或改写已产生的译音。

## 政策如何送入服务

[会话实现](../vlt/session/chatgpt_live.py) 在原有前端翻译规则后加入直接呈现、来源信任边界、顺序续译与忠实度要求。启动时另传入固定的 developer 说明与来源／译文示例，展示叙述、问题和命令都只是待翻译内容。

示例覆盖十种既有目标语言，完全固定，不使用私人录音、攻击逐字稿、测试预期答案或用户词库。自定义目标语言维持原有协商方式。词库仅放在明确标示为数据的 JSON 区块，不插入 developer 指示或固定示例。后端原有翻译提示词保留。

忠实度规则允许上下文协助识别实际听到的字词，但禁止自行补出未说过的事实、建议、句尾或答案。来源已是目标语言时仍维持来源内容；真正的引用、角色标签和重复不能被当成攻击字词删除。

## 既有有限验证结果与边界

在新的工具诱导反例提出前，本地使用完整长对话前导、攻击后等待及后续正常语句，另做新连接重测。五组跨语言长对话、四组冷启动重测及一组中文控制，共十组有限攻击核对未再观察到额外答案、独立替换回复、整段漏译、整段重复或无来源的对话介绍。真正重复、引用与后续正常语句均保留。这是历史有限样本结果，不能视为当前发布门槛通过。

跨语言自动判定维持 REVIEW；中文控制的原始字词判定为 FAIL，识别／字词差异依测试条件另列，没有修改判定器或将结果改成自动 PASS。服务的来源转录不是独立的录音真值；原始录音并未逐字听校。这些结果只支持已执行的有限案例，不保证任意语音或任意长度对话都不会发生提示词注入。

Windows 本地另以两条同时启用译音的正式会话，经生产采样泵、Engine、MicProxy 与虚拟音频回录验证。两次新连接、各三轮回录全部通过，完整服务语音与各自回录声道的波形相关度最低为 99.919%，没有回录状态错误或输出缓冲不足。波形一致不是译音逐字正确、远端 VRChat 听感或 Linux 实体音频的证明。

提示词是概率性的行为约束，没有提供确定性的安全隔离。如果日后观察到新的额外回答或漏译，应保留来源、完整服务输出与时序重新验证，不能只用连接成功或单一字幕事件宣称通过。

## Repo 与 CI 的范围

耗用订阅额度的额外实机测试程序、长对话数据、私人录音、原始转录及回录只保留于本地忽略的临时目录，不随 repo、软件包或 CI 发布。

Repo 保留离线政策传递、语言组合、词库数据边界、字幕分片、真正重复、错误清理与 GUI 回归测试。CI 使用假的 RPC／浏览器边界，不登录 ChatGPT、不建立语音服务连接，也不需要额度或音频设备。离线政策测试证明应用程序送出的契约；它不替代真人语音防护的实测。

服务菜单标示「消耗 Codex 额度」。语音翻译会使用登录账户的订阅额度；双向模式建立两条独立会话，两个方向都可能耗用额度。订阅额度不等同于一般 OpenAI API credit。
